岗位要求与知识路线

先看清"他们要什么"，再决定"我补什么"。本页整理了 GPU / 系统软件方向的真实招聘要求， 并映射到本站各个专题。

一句话结论 这个方向的面试不是考"你知不知道 XX 概念"，而是考你是否真正在系统层工作过： 你写过驱动吗？你调过内存一致性问题吗？你在多核并发下定位过偶发 hang 吗？ 所有知识都要能落到"我遇到过 / 我怎么解决的"这个答案上。

从后端到驱动：常见的能力落差

后端 → 驱动是"越往下走"，需要补的不只是知识，还有思维方式：

落差 1：从"逻辑正确"到"时序正确" 后端代码错了重跑一次基本就过去了。驱动错了会偶发 hang、数据损坏、整机 panic， 而且可能几千次才复现一次。所以面试官会追问：你怎么证明你的并发代码是对的？ 你遇到过 race condition 吗？怎么定位的？
落差 2：从"资源无限"到"资源是硬约束" 后端可以加机器、加内存。驱动里 kmalloc(GFP_ATOMIC) 失败就是失败， 中断上下文不能睡，栈只有 16KB（x86-64 内核栈典型 16KB）。 这些约束必须是条件反射，而不是"查一下再说"。
落差 3：从"看到现象"到"看到硬件" 后端 debug 看日志。驱动 debug 要看寄存器、看 DMA 地址、看 PCIe 配置空间、 用逻辑分析仪或 ftrace 看事件顺序。你需要建立从软件到硬件的心智模型。
你的优势 后端背景带来的大型系统设计能力、可观测性思维、工程化习惯恰恰是很多纯内核背景的人欠缺的。 NVIDIA 的 JD 反复强调 "large codebases"、"cross-team"、"maintainable and well-tested code" —— 这些是你的加分项，不要丢。

8 周准备路线

假设每天 2 小时、周末 4 小时。顺序很重要：先补基础，再攻专项。

周次主题目标

W3操作系统与内核基础进程/线程、调度、虚拟内存、页表、系统调用路径

W5驱动开发字符设备、file_operations、ioctl、mmap、DMA、中断处理
W6GPU 软件栈UMD/KMD 分层、CUDA 上下文/流、显存管理、命令提交、同步原语
W7虚拟化 + 调试性能KVM/VFIO/SR-IOV/IOMMU；perf、ftrace、eBPF、GDB
W8网络 + 复盘TCP/IP、epoll、RDMA；刷错题，把 Q&A 讲一遍
面试中最容易翻车的地方
  • 只会背不会写：让你手写一个自旋锁 / 环形缓冲区 / 无锁队列，写不出来。
  • 说不出数字：页大小多少？内核栈多大？中断上下文为什么不能睡？答不上具体值。
  • 没有主线：讲项目像流水账，说不出"我做的技术决策是什么、为什么这样选"。
  • 不懂硬件：面 GPU 岗却讲不清 GPU 为什么快、显存和 CPU 内存的本质区别。
